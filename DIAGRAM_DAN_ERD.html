2. Activity Diagrams (Alur Proses Sistem)

Bab IV Sub-Bab 4.1

A. Activity Diagram: Alur Autentikasi Login Pengguna

Menggambarkan alur validasi pengguna mulai dari input kredensial, verifikasi hash bcrypt di backend, hingga pembuatan token JWT.

flowchart TD
    StartLogin([Mulai]) --> BukaApp[Buka Aplikasi Mobile Dapoer Berkah]
    BukaApp --> CekToken{Pemeriksaan Token di SharedPreferences}
    CekToken -- Token Ada & Valid --> BukaDashboard[Langsung Masuk ke Home Dashboard]
    CekToken -- Token Tidak Ada / Expired --> FormLogin[Tampilkan Halaman Login]
    
    FormLogin --> InputKredensial[Pengguna Memasukkan Email & Password]
    InputKredensial --> KlikMasuk[Klik Tombol 'Masuk']
    KlikMasuk --> ValidasiClient{Validasi Format Email & Password}
    
    ValidasiClient -- Tidak Lengkap --> AlertClient[Tampilkan Pesan Peringatan Input]
    AlertClient --> FormLogin
    
    ValidasiClient -- Valid --> KirimRequest[Kirim POST /api/auth/login ke Backend]
    KirimRequest --> BackendQuery[Backend Mencari Pengguna Berdasarkan Email]
    
    BackendQuery --> CekUserAda{User Ditemukan di DB?}
    CekUserAda -- Tidak --> Return401[Kembalikan HTTP 401 Unauthorized]
    Return401 --> SnackBarError[Tampilkan SnackBar: Email atau password tidak valid]
    SnackBarError --> FormLogin
    
    CekUserAda -- Ya --> VerifikasiHash{Bcrypt Compare Password}
    VerifikasiHash -- Hash Tidak Cocok --> Return401
    
    VerifikasiHash -- Hash Cocok --> TerbitkanJWT[Generate JWT Token & Payload User Role]
    TerbitkanJWT --> Return200[Kembalikan HTTP 200 OK + Token + Profil]
    Return200 --> SimpanToken[Aplikasi Menyimpan Token ke SharedPreferences]
    SimpanToken --> BukaDashboard
    BukaDashboard --> EndLogin([Selesai])

B. Activity Diagram: Alur Tambah Menu Baru & Upload Foto (Khusus Role Admin)

Menggambarkan proses penambahan produk lengkap dengan pemeriksaan otorisasi role di backend dan pengunggahan file fisik gambar.

flowchart TD
    StartAdd([Mulai]) --> NavigasiForm[Admin Membuka Form Tambah Menu Baru]
    NavigasiForm --> PilihKategori[Pilih Kategori Menu dari Dropdown]
    PilihKategori --> IsiForm[Isi Nama, Harga, Stok, dan Deskripsi Menu]
    IsiForm --> KetukFoto[Ketuk Kotak Unggah Foto]
    KetukFoto --> ModalPicker[Muncul Dialog: Kamera atau Galeri Foto]
    ModalPicker --> AmbilGambar[Pilih Gambar Menggunakan image_picker]
    AmbilGambar --> PreviewGambar[Pratinjau Foto Ditampilkan di Form]
    
    PreviewGambar --> KlikSimpan[Klik Tombol 'Simpan Menu Baru']
    KlikSimpan --> ValidasiForm{Validasi Form Lengkap?}
    ValidasiForm -- Belum Lengkap --> PesanErrorForm[Tampilkan Peringatan Field Wajib]
    PesanErrorForm --> IsiForm
    
    ValidasiForm -- Lengkap --> KirimMultipart[Kirim Request Multipart/Form-Data ke Backend + Bearer JWT]
    KirimMultipart --> AuthCheck{authMiddleware: Token Valid?}
    AuthCheck -- Tidak --> Respon401[HTTP 401: Akses Ditolak]
    
    AuthCheck -- Ya --> RoleCheck{roleMiddleware: Role == 'admin'?}
    RoleCheck -- Bukan Admin --> Respon403[HTTP 403: Role kasir ditolak]
    
    RoleCheck -- Admin --> MulterUpload{uploadMiddleware: Validasi File}
    MulterUpload -- File Bukan Gambar / >20MB --> Respon400[HTTP 400: Format file tidak didukung]
    
    MulterUpload -- Valid --> SimpanFisik[Simpan File Foto ke Server Folder /uploads/]
    SimpanFisik --> InsertDB[INSERT INTO products VALUES (...)]
    InsertDB --> Respon201[HTTP 201 Created + Data Produk Lengkap]
    
    Respon201 --> SnackBarSukses[Tampilkan SnackBar: Menu baru berhasil ditambahkan]
    SnackBarSukses --> RefreshKatalog[Katalog Produk Di-refresh Otomatis]
    RefreshKatalog --> EndAdd([Selesai])
    
    Respon401 --> EndAdd
    Respon403 --> EndAdd
    Respon400 --> FormTambahUlang[Kembali ke Form dengan Pesan Error]
    FormTambahUlang --> EndAdd

C. Activity Diagram: Alur Hapus Menu dengan Konfirmasi Pengguna

Menggambarkan alur perlindungan data melalui dialog konfirmasi sebelum record produk di database dan file foto fisik dihapus.

flowchart TD
    StartDel([Mulai]) --> BukaDetail[Admin Membuka Halaman Detail Menu]
    BukaDetail --> KlikHapus[Klik Tombol 'Hapus Menu']
    KlikHapus --> TampilDialog[Muncul AlertDialog Konfirmasi: 'Apakah Anda yakin ingin menghapus menu ini?']
    TampilDialog --> PilihanUser{Keputusan Pengguna}
    
    PilihanUser -- Batal --> TutupDialog[Tutup Dialog & Tidak Ada Perubahan Data]
    TutupDialog --> EndDel([Selesai])
    
    PilihanUser -- Hapus --> KirimDelete[Kirim DELETE /api/products/:id + Token JWT]
    KirimDelete --> CekIzinRole{Pemeriksaan Role Admin}
    CekIzinRole -- Ditolak --> Respon403Del[HTTP 403 Forbidden]
    
    CekIzinRole -- Disetujui --> CekFotoAda{Produk Memiliki Foto Fisik?}
    CekFotoAda -- Ada --> HapusFile[fs.unlinkSync: Hapus File Gambar dari /uploads/]
    CekFotoAda -- Tidak Ada --> EksekusiQuery
    HapusFile --> EksekusiQuery[DELETE FROM products WHERE id = ?]
    
    EksekusiQuery --> Respon200Del[HTTP 200 OK: Produk berhasil dihapus]
    Respon200Del --> PopDetail[Tutup Halaman Detail & Kembali ke Katalog]
    PopDetail --> UpdateState[ProductProvider Menghapus Item dari State List]
    UpdateState --> SnackBarDel[Tampilkan SnackBar Berhasil Dihapus]
    SnackBarDel --> EndDel

4. Entity Relationship Diagram (ERD)

Bab IV Sub-Bab 4.2

Menggambarkan skema basis data relasional MySQL pada Aiven Cloud, mencakup tabel, tipe data, atribut, Primary Key (PK), Foreign Key (FK), dan kardinalitas relasi. 

erDiagram
    users {
        int id PK "AUTO_INCREMENT, Not Null"
        varchar name "VARCHAR(100), Not Null"
        varchar email UK "VARCHAR(100), Not Null, Unique"
        varchar password "VARCHAR(255), Not Null, Bcrypt Hash"
        enum role "ENUM('admin', 'kasir'), Default 'kasir'"
        timestamp created_at "TIMESTAMP, Current Timestamp"
        timestamp updated_at "TIMESTAMP, On Update Current Timestamp"
    }

    categories {
        int id PK "AUTO_INCREMENT, Not Null"
        varchar name "VARCHAR(100), Not Null"
        text description "TEXT, Nullable"
        timestamp created_at "TIMESTAMP, Current Timestamp"
        timestamp updated_at "TIMESTAMP, On Update Current Timestamp"
    }

    products {
        int id PK "AUTO_INCREMENT, Not Null"
        int category_id FK "INT, Not Null, Foreign Key -> categories(id)"
        varchar name "VARCHAR(150), Not Null"
        text description "TEXT, Nullable"
        decimal price "DECIMAL(12,2), Default 0.00"
        int stock "INT, Default 0"
        varchar image_url "VARCHAR(255), Nullable (Nama File Foto)"
        timestamp created_at "TIMESTAMP, Current Timestamp"
        timestamp updated_at "TIMESTAMP, On Update Current Timestamp"
    }

    categories ||--o{ products : "has / menaungi (1 to Many, ON DELETE CASCADE)"
Penjelasan Kardinalitas Relasi:
  • One-to-Many (1 : N): Setiap 1 Kategori (misal: Makanan Utama) dapat memiliki 0 atau banyak Produk hidangan terkait.
  • Foreign Key Constraint: Kolom products.category_id mereferensikan categories.id dengan aturan ON DELETE CASCADE dan ON UPDATE CASCADE, sehingga integritas relasi antar tabel tetap konsisten.

A. Tabel: users

Nama Field Tipe Data Null Key Default Keterangan
id INT(11) NO PRI AUTO_INCREMENT Identifier unik pengguna (Primary Key)
name VARCHAR(100) NO None Nama lengkap pegawai / pengelola
email VARCHAR(100) NO UNI None Email akun unik untuk autentikasi (Unique Key)
password VARCHAR(255) NO None Kata sandi terenkripsi hash satu arah (bcrypt)
role ENUM('admin', 'kasir') NO 'kasir' Peranan pengguna untuk otorisasi RBAC
created_at TIMESTAMP NO CURRENT_TIMESTAMP Waktu registrasi akun
updated_at TIMESTAMP NO CURRENT_TIMESTAMP Waktu terakhir data diperbarui

B. Tabel: categories (Data Utama 1)

Nama Field Tipe Data Null Key Default Keterangan
id INT(11) NO PRI AUTO_INCREMENT Identifier unik kategori menu (Primary Key)
name VARCHAR(100) NO None Nama label kategori (Makanan Utama, Minuman, Snack)
description TEXT YES NULL Penjelasan singkat kategori hidangan
created_at TIMESTAMP NO CURRENT_TIMESTAMP Waktu kategori dibuat
updated_at TIMESTAMP NO CURRENT_TIMESTAMP Waktu terakhir kategori diperbarui

C. Tabel: products (Data Utama 2)

Nama Field Tipe Data Null Key Default Keterangan
id INT(11) NO PRI AUTO_INCREMENT Identifier unik produk menu (Primary Key)
category_id INT(11) NO MUL None Foreign Key ke categories(id) (ON DELETE CASCADE)
name VARCHAR(150) NO None Nama menu makanan / minuman
description TEXT YES NULL Deskripsi porsi, rasa, dan bahan
price DECIMAL(12,2) NO 0.00 Harga jual produk dalam mata uang Rupiah
stock INT(11) NO 0 Kuantitas stok menu yang tersedia
image_url VARCHAR(255) YES NULL Nama file gambar terupload di media penyimpanan server
created_at TIMESTAMP NO CURRENT_TIMESTAMP Waktu produk dibuat
updated_at TIMESTAMP NO CURRENT_TIMESTAMP Waktu terakhir produk diperbarui
